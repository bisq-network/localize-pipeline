# Contributing to Localize Pipeline

Thank you for wanting to help improve this project!

## Getting Started

1. Fork [bisq-network/localize-pipeline](https://github.com/bisq-network/localize-pipeline),
   then clone your fork:

   ```bash
   git clone https://github.com/YourUsername/localize-pipeline.git
   cd localize-pipeline
   ```

2. Create a virtual environment with Python 3.11 or newer. The commands in this
   guide expect it in `venv/`:

   ```bash
   python3.11 -m venv venv
   source venv/bin/activate
   # or for Windows:
   # venv\Scripts\activate
   ```

3. Install the locked development dependencies. This lockfile includes the
   runtime dependencies, `pytest` and `ruff`:

   ```bash
   pip install -r requirements-dev.txt
   ```

4. Run the linter and the tests. Neither needs network access or a real API
   key; the tests use mocked model responses.

   ```bash
   ruff check .
   pytest -q
   ```

[docs/repository-structure.md](docs/repository-structure.md) explains where
each part of the code lives.

## Pull Request Guidelines

- All PRs should be made against the `main` branch.
- Include a concise description of the changes.
- Use TDD for behavior changes: add or change a test first, then the code.
- Ensure that `ruff check .` and `pytest -q` pass locally. CI runs the same two
  commands on Python 3.11 and 3.12.
- Keep public docs, examples, and tests aligned with any API or configuration
  changes.

## Python Dependency Management

This project uses `pip-tools` to manage Python dependencies, ensuring reproducible builds.

-   **`requirements.in`**: This file contains the primary, top-level dependencies for the application (e.g., `openai`, `pyyaml`).
-   **`requirements-dev.in`**: This file contains dependencies used only for development and testing (e.g., `pytest`).
-   **`requirements.txt`** and **`requirements-dev.txt`**: These are the **locked** dependency files generated by `pip-compile`. They contain the exact versions and hashes of all top-level and transitive dependencies. **Do not edit these files manually.**

### Updating Dependencies

When you need to add or update a Python dependency, please edit the appropriate `.in` file:

-   `requirements.in` for production dependencies.
-   `requirements-dev.in` for development and testing dependencies.

After editing, follow these steps:

1.  `pip-tools` is part of the development dependencies, so it is already installed in your environment.
2.  Navigate to the project's root directory.
3.  Re-compile the locked requirement files with the same commands that produced them. The development lockfile needs `--allow-unsafe` because it pins `pip` and `setuptools`:
    ```bash
    pip-compile --generate-hashes --output-file=requirements.txt requirements.in
    pip-compile --allow-unsafe --generate-hashes --output-file=requirements-dev.txt requirements-dev.in
    ```
4.  Commit the changes to both the `.in` file and the generated `.txt` file to your pull request.

### Installing the locked dependencies locally
Use pip-tools' pip-sync to exactly match the lockfiles:
```bash
pip-sync requirements.txt requirements-dev.txt
```

## Code Style
This project uses `ruff` for linting. Run it from the project root before you
submit a pull request:
```bash
ruff check .
```
`ruff check . --fix` fixes simple findings automatically.

## Code of Conduct

Be respectful and constructive in your interactions. We welcome all suggestions!
